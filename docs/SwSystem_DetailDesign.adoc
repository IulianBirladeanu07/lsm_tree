== Overview

A Log-Structured Merge Tree implemented in C++20 as a Master's dissertation project at Politehnica Timișoara.
The primary goal is high write throughput via sequential disk I/O and in-memory buffering,
with pluggable compaction strategies (Leveled, Tiered) for comparing RUM tradeoffs.

=== Design Goals

* High write throughput — all writes are sequential (WAL append + MemTable flush to SSTable)
* Concurrent reads without blocking writers — active MemTable accessed via `atomic<shared_ptr>`
* Durability — CRC32-verified WAL, full crash recovery on startup
* Configurable false positive rate per SSTable via Bloom filters
* Background compaction via a dedicated ThreadPool
* Interchangeable compaction strategies with no changes to `LSMTree`

=== RUM Conjecture Tradeoffs

[cols="1,1,1,1", options="header"]
|===
| Strategy | Write Amplification | Read Amplification | Space Amplification
| Leveled  | High (~10-30x)      | Low (~2-5x)        | Low (~1.1x)
| Tiered   | Low (~3-10x)        | High (~10-30x)     | High (~2-3x)
|===

== Architecture Overview

`LSMTree` is the single public entry point. All other components are internal and communicate through well-defined interfaces.

image::lsm_01_core.png[Core architecture diagram]

=== Components

[cols="1,3", options="header"]
|===
| Component | Role
| `LSMTree` | Entry point. Orchestrates WAL, MemTable, LevelManager, and compaction.
| `WAL` | Append-only on-disk log. First write for every put/del. Replayed on startup for recovery.
| `MemTable` | In-memory write buffer backed by `ConcurrentSkipList`. Becomes immutable when full.
| `ConcurrentSkipList` | Internal data structure of MemTable. Mutex-protected writes, lock-free reads via `atomic<Node*>`.
| `LevelManager` | Manages the L0–LN level hierarchy and the SSTable list per level.
| `SSTable` | Immutable on-disk sorted file. Written once by `SSTableBuilder`, read-only afterward.
| `BlockCache` | Thread-safe LRU cache for loaded blocks. Reduces disk I/O for hot data.
| `BloomFilter` | Probabilistic per-SSTable filter. Skips disk reads when a key is definitely absent.
| `CompactionScheduler` | Runs compaction jobs in the background via a `ThreadPool`.
| `MergingIterator` | Min-heap over N child iterators. Used in both `scan()` and compaction.
|===

== Write Path

image::lsm_05_write_path.png[Write path sequence diagram]

Every `put(key, value)` executes three steps synchronously; the rest happens in the background.

1. `WAL::append()` — record persisted to disk before anything else
2. `MemTable::put()` — inserts into the skip list, updates the atomic size counter
3. If the MemTable is full and `try_mark_flushing()` succeeds (CAS) → `flush_memtable()`

`flush_memtable()` does the following:

* Pushes the old MemTable into `imm_` (the immutable list)
* Atomically stores a new empty MemTable into `mem_`
* Submits a background task to the ThreadPool that builds the SSTable on disk, adds it to L0, truncates the WAL, and calls `compaction_->schedule()`

`del(key)` is identical to `put`, but writes the sentinel value `"\xFF"` (tombstone).

=== Write Path Concurrency

There is one active writer per MemTable at a time (internal mutex in `ConcurrentSkipList`).
Readers traverse the list without a lock via `atomic<Node*>` pointers.
The active ↔ immutable MemTable swap uses `atomic<shared_ptr<MemTable>>` —
readers already holding a reference to the old MemTable finish without blocking.

== Read Path

image::lsm_06_read_path.png[Read path sequence diagram]

`get(key)` searches from newest to oldest data:

1. Active MemTable — `O(log n)` in the skip list
2. Immutable MemTable list — newest-first
3. Level 0 SSTables — *all* files (key ranges may overlap), each guarded by a Bloom filter
4. Level 1..N SSTables — binary search on key range, at most one file per level

For each SSTable: if `BloomFilter::may_contain()` returns false, the file is skipped entirely.
If the filter says "maybe", the relevant block is loaded and scanned linearly.

Tombstones (`"\xFF"`) are filtered in both `get()` and `scan()` — the caller receives `nullopt`.

== SSTable File Format

image::lsm_02_sstable.png[SSTable component diagram]

The file is written sequentially by `SSTableBuilder` and never modified after `finish()`.

[cols="1,3", options="header"]
|===
| Section | Contents
| Data Block 0..N | Sorted key/value pairs. Each block ~4KB (configurable). Ends with CRC32.
| Index Block | One `IndexEntry` per block: `first_key`, `last_key`, `offset`, `size`. Binary serialized.
| Filter Block | Serialized `BloomFilter`: `num_hashes` (8B) + bit vector.
| Footer | `index_offset` (8B) + `filter_offset` (8B) + `magic` (8B) = 24 bytes fixed.
|===

=== Block Entry Layout

Each entry within a data block:

----
[ key_len: uint32 | val_len: uint32 | key: key_len bytes | value: val_len bytes ]
----

The last 4 bytes of each block are a CRC32 checksum over the entire block content.

=== SSTable Lookup

. `BloomFilter::may_contain(key)` — if false, stop immediately
. Scan `IndexBlock::entries()` linearly for the first entry where `key <= last_key`
. `pread()` the block at `entry.offset`, `entry.size` bytes
. Linear scan within the block until the key is found or the block is exhausted

== Compaction

image::lsm_03_compaction.png[Compaction component diagram]

`CompactionScheduler::schedule()` is called after every MemTable flush.
It picks a job via the active strategy and submits it to the ThreadPool.

`run_compaction()` steps:

. Creates one `SSTableIterator` per SSTable in `job.inputs`
. Wraps all iterators in a `MergingIterator`
. Iterates the merged output, dropping tombstones
. Builds a new SSTable via `SSTableBuilder`
. Calls `LevelManager::replace_level(inputs, {new_sst}, output_level)`

=== LeveledCompaction

Score per level: `total_size / (base_bytes * multiplier^level)`.
If score > 1.0, all SSTables on that level are taken as input and merged into the next level.

=== TieredCompaction

If the number of SSTables on a level >= `size_ratio`, the entire level is compacted into the next.
Does not consider file sizes — only file count.

== Iterator Hierarchy

image::lsm_04_iterators.png[Iterator hierarchy diagram]

All iterators implement `IIterator`:

[source,cpp]
----
class IIterator {
public:
    virtual void             seek(std::string_view key) = 0;
    virtual void             next() = 0;
    virtual bool             valid() const = 0;
    virtual std::string_view key()   const = 0;
    virtual std::string_view value() const = 0;
};
----

[cols="1,3", options="header"]
|===
| Iterator | Data source
| `SkipListIterator` | Wraps `ConcurrentSkipList::Iterator`. Used for MemTable in `scan()`.
| `BlockIterator` | Scans a single `Block` by linear offset. Seek is a linear scan from the start.
| `SSTableIterator` | Scans all blocks of one SSTable. Seek uses binary search on the IndexBlock.
| `MergingIterator` | Min-heap over N `IIterator*` children. Always yields the smallest key.
|===

`MergingIterator` uses `IteratorComparator: a->key() > b->key()` so the smallest key is at the top.
On `seek(key)`, all children are re-seeked and the heap is rebuilt from scratch.

`LSMTree::scan()` builds a `MergingIterator` over all sources, then deduplicates keys and filters tombstones in the caller.

=== WAL

On-disk record format:

----
[ CRC32: 4B | key_len: 4B | val_len: 4B | key: key_len B | value: val_len B ]
----

Delete records use `val_len = 0xFFFFFFFF` as a sentinel; no value bytes follow in the payload.

Recovery reads records one by one, verifies CRC32, and stops at the first corrupt record.
The WAL is truncated after each successful MemTable flush.

=== MemTable

[source,cpp]
----
class MemTable {
public:
    void                         put(std::string_view key, std::string_view value);
    std::optional<std::string>   get(std::string_view key);
    bool                         is_full() const;
    bool                         try_mark_flushing();  // CAS — returns true exactly once
    ConcurrentSkipList::Iterator iterator() const;
    std::unique_ptr<IIterator>   iiterator() const;
};
----

`is_full()` returns true when `size_ >= capacity_`.
`put()` sets `writable_ = false` once capacity is reached.
`try_mark_flushing()` does a CAS on `flushing_` — guarantees flush is triggered exactly once.

=== ConcurrentSkipList

12 levels, randomized height with geometric distribution (p=0.5).
Writes are serialized by `std::mutex`. Reads traverse `atomic<Node*>` pointers without a lock.
No memory reclamation — nodes live as long as the skip list.

=== SSTable / SSTableBuilder

`SSTableBuilder` is the only way to create an SSTable.
`finish()` flushes the last block, writes the Index Block, Filter Block, and Footer, closes the file descriptor, and returns `SSTable::open(path)`.

`SSTable` does not receive a `BlockCache` — the cache is managed externally by `LSMTree` and is not wired into `SSTable::get()` in the current implementation.

=== BloomFilter

Parameters derived from expected key count and target FPR:

* `num_bits = -n * ln(p) / ln(2)²`
* `num_hashes = (bits/n) * ln(2)`

Double-hashing (Kirsch-Mitzenmacher): `h_i(x) = hash1(x) + i * hash2(x)` where
`hash2 = hash1 ^ kFibHashConstant (0x9e3779b97f4a7c15)`.

=== CompactionScheduler

[source,cpp]
----
class CompactionScheduler {
public:
    CompactionScheduler(std::unique_ptr<ICompactionStrategy> strategy,
                        std::shared_ptr<LevelManager>        levels,
                        std::shared_ptr<ThreadPool>          thread_pool,
                        std::function<std::string()>         path_generator);
    void schedule();
};
----

`schedule()` calls `strategy_->pick_job()`. If the job has no inputs, it returns immediately.
`run_compaction()` runs inside the ThreadPool and never blocks the write path.

=== ThreadPool

`std::jthread` workers, woken by `std::condition_variable`.
`shutdown()` sets `stop_ = true` and notifies all workers.
`submit()` after `shutdown()` throws `std::runtime_error`.

== C++20 Features

[cols="1,3", options="header"]
|===
| Feature | Where and why
| `std::jthread` | `ThreadPool` workers — automatic join on destruction, no explicit `join()` needed
| `std::atomic<shared_ptr<T>>` | Lock-free MemTable swap in `flush_memtable()`
| `std::span` | Zero-copy buffer views in `WAL`, `BloomFilter::deserialize()`, `Footer::deserialize()`
| `std::format` | SSTable filename generation: `sst_{:06d}.sst`
| `std::shared_mutex` | `LevelManager` and `imm_` list — N concurrent readers, single writer
|===

== Known Limitations

* WAL is truncated after MemTable flush, not after compaction — a crash mid-compaction may leave orphaned SSTable files on disk
* No MVCC or snapshot isolation — last write wins
* `BlockCache` is sized in `LSMOptions` but not wired into `SSTable::get()` in the current implementation
* The Leveled vs Tiered difference is not visible in benchmarks at 100k keys — compaction pressure is insufficient; it becomes measurable at dataset sizes larger than available RAM
* No prefix compression in data blocks

The Leveled vs Tiered gap is small at this dataset size — insufficient compaction pressure to expose the write amplification tradeoff.
